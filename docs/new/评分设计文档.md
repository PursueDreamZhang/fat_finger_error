# 期货乌龙指日线初筛器评分设计文档

> 本文档只负责约束第一版日线初筛器的评分体系与等级判定规则。主设计稿与实现计划只引用本文，不再重复维护评分细节。后续如果调整评分逻辑，应优先修改本文档。

## 1. 文档目标

本文档回答五个问题：

1. 单个 `合约-交易日` 的候选分如何计算
2. 为什么第一版评分体系收缩为 `A/C/E`
3. `A` 为什么使用 `close`，以及 `close` 在哪些地方不应进入主判断
4. `C` 和 `E` 里的“活跃合约”如何正式定义
5. 最终候选等级如何从分数得出

本文档不负责描述：

- 数据访问层
- 缓存策略
- HTML 输出结构
- 用户入口

这些内容由主设计稿负责。

## 2. 评分对象与基本约束

### 2.1 评分对象

评分对象固定为：

- 单个 `合约-交易日`

也就是每条评分记录都对应：

- 一个具体品种
- 一个具体合约
- 一个具体交易日

### 2.2 历史窗口

第一版所有历史比较统一使用：

- 向前 `20` 个有效交易日
- 不包含当天
- 至少需要 `10` 个有效历史样本

若有效历史样本不足 `10`：

- 由样本过滤层标记为数据不足类状态
- 实现中统一落地为 `sample_status = invalid_insufficient_history`
- 该样本保留在结果集中，但按无效样本处理
- 无效样本统一使用：

```text
A = 0
C = 0
E = -20
```

### 2.3 第一版总分公式

第一版评分体系固定收缩为：

```text
candidate_score = A + C + E
candidate_score = min(100, max(0, candidate_score))
```

其中：

- `A` 自身极值异常分
- `C` 同品种结构极值异常分
- `E` 可信度惩罚分

这代表第一版日线初筛器的核心判断是：

1. 这个合约自己当天的极值是否异常
2. 这个合约相对同品种其他活跃合约的结构是否异常
3. 这条样本到底值不值得信

## 3. 设计原则

### 3.1 为什么第一版只保留 `A/C/E`

第一版不再把 `B` 和 `D` 独立保留为主评分项，原因如下：

- `B` 本质上依赖“收盘是否修复”的判断。对于只有日线的数据，这类信息更适合做解释字段，不适合作为核心加分项。
- `D` 想表达的“是不是只有这个合约异常”，本质上属于结构异常的一部分，应该并回 `C` 的定义，而不是单独拆出一项。

因此，第一版主评分只保留：

- `A`：自己今天怪不怪
- `C`：相对同品种其他活跃合约，自己今天怪不怪
- `E`：这条记录靠不靠谱

### 3.2 `close` 的使用边界

第一版对 `close` 的使用原则固定为：

- `A` 可以使用 `close`
- `C` 不对 `close` 本身做主判断
- `E` 不使用 `close`

这条边界非常重要。

#### 3.2.1 为什么 `A` 使用 `close`

`A` 的任务是衡量：

- 这个合约自己当天盘中极值到底偏离了多远

这里使用 `close` 而不是 `pre_close`，原因是：

1. `A` 只看该合约自身，不做跨合约结构比较
2. 对于自身波动强度，`close` 更像当天的价格尺度
3. 若当天整体价格水平已经显著抬升或下移，继续用 `pre_close` 会把前一日价格锚混进来，削弱 `A` 作为“当天自身极值异常强度”的纯度

因此，`A` 使用 `close` 的含义是：

- 用当天最终价格尺度去衡量盘中极值有多极端

这里再补一条边界说明：

- `A` 不是在衡量“相对前一日正常价格锚偏离了多少”
- `A` 衡量的是“相对当天最终价格尺度，盘中极值有多极端”

这意味着：

- 若盘中异常很深，但收盘没有修回，`A` 可能不会像基于 `pre_close` 的定义那样继续放大
- 这是第一版有意识接受的取舍，不是遗漏

#### 3.2.2 为什么 `C` 不单独审计 `close`

`C` 的任务是衡量：

- 这个合约相对同品种其他活跃合约，盘中结构有没有被打歪

因此，`C` 的主证据应当来自：

- `high`
- `low`

而不是：

- `close`

原因是：

1. 乌龙指可能发生在任何时间段，主证据通常体现在异常高点或低点
2. 收盘价可能已经完全修复，不能代表盘中是否出现过异常成交
3. 如果把 `close` 也作为 `C` 的主判断项，会把“盘中结构异常”和“收盘结果”混在一起

因此，“把 `close` 从主评分里拿掉”在本文档中的精确含义是：

- **只针对 `C` 的判断对象**
- 不是说整个评分体系都不能使用 `close`
- 也不是说 `C` 的公式里完全不能引用 `close` 作为归一化尺度

### 3.3 活跃合约定义

`C` 和 `E` 都依赖“活跃合约”的正式定义。

对任意一个 `commodity + trade_date`，第一版按以下顺序确定活跃合约集合：

1. `sample_status == valid`
2. `volume > 0`
3. 在同品种同日内按 `volume` 从高到低排序
4. 取排序后的前 `5` 个合约作为“同日活跃合约集合”

补充规则：

- 若满足条件的合约不足 `5` 个，则取全部
- 若满足条件的合约不足 `2` 个，则认为当日没有足够的结构比较基础

这里再明确一条：

- “前 `5` 个活跃合约”是第一版的工程简化规则
- 它的目标是先稳定排除明显不活跃的尾部合约
- 它不是期限结构比较的理论最优边界
- 后续若发现不同品种的活跃层级差异很大，可以再单独升级这条规则

对某个目标合约来说：

- `active_peer_count = 同日活跃合约集合去掉目标合约后的数量`

也就是：

- 自己不算自己的活跃对照

### 3.4 可比性稳定性与目标合约自身流动性

第一版除了定义“同日活跃合约集合”，还要显式处理两个容易漂移的问题：

1. `C1` 的历史序列会随着换月和活跃合约迁移而发生可比性波动
2. 目标合约自己如果过薄，可能因为一次小成交被高估

这两个问题都不再混进 `C`，统一交给 `E` 处理。

#### 3.4.1 可比性稳定性

第一版承认：

- `structure_residual` 是基于“同日活跃合约前 5 名”的横截面基线
- 这条基线会随换月和活跃迁移发生变化

但第一版不把它当成致命问题，而是用两条规则控制：

1. `C1` 的历史比较只使用过去 `20` 个有效交易日中：
   - `sample_status == valid`
   - `active_peer_count >= 2`
   的样本
2. 若当天的活跃可比合约数明显弱于该合约过去 `20` 日常态，则不否定 `C`，而是通过 `E` 降权

第一版把“明显弱于常态”定义为：

```text
active_peer_count < max(2, rolling_median_active_peer_count - 1)
```

其中：

- `rolling_median_active_peer_count`
  - 指该合约过去 `20` 个有效交易日的 `active_peer_count` 中位数

若满足上述条件，则记：

- `peer_comparability_weak_flag = True`

#### 3.4.2 目标合约自身流动性

第一版不要求目标合约必须进入“同日活跃合约前 5 名”，因为某些真实异常就可能发生在相对边缘但仍有交易的合约上。

但第一版要求避免把“极薄尾部合约的一次小成交”高估成强异常，因此增加：

- `target_liquidity_weak_flag`

定义为：

```text
today_volume < 0.2 * rolling_median_volume
AND
today_volume < 0.3 * peer_volume_median
```

其中：

- `rolling_median_volume`
  - 指该合约过去 `20` 个有效交易日的成交量中位数
- `peer_volume_median`
  - 指同日活跃可比合约的成交量中位数

若同时满足上述两个条件，则认为：

- 该目标合约当天自身流动性偏弱
- 分数应保留，但可信度应下降

## 4. A. 自身极值异常分

### 4.1 取值范围

- `0 ~ 20`

### 4.2 业务含义

`A` 只回答一个问题：

- 这个合约自己当天盘中极值是否显著异常

它不负责判断：

- 相对其他合约是否异常
- 是否只有它自己异常
- 这条样本是否可信

### 4.3 定义

```text
range_pct = (high - low) / close

extreme_pct = max(
  (high - close) / close,
  (close - low) / close
)
```

这两个量都只依赖：

- `high`
- `low`
- `close`

不使用：

- `pre_close`

### 4.4 评分逻辑

#### A1. 振幅异常分：`0 ~ 12`

拿 `range_pct` 与过去 `20` 个有效交易日的历史分布比较：

- `< P90`：`0`
- `P90 <= value < P95`：`4`
- `P95 <= value < P99`：`8`
- `>= P99`：`12`

#### A2. 极值异常分：`0 ~ 8`

拿 `extreme_pct` 与过去 `20` 个有效交易日的历史分布比较：

- `< P90`：`0`
- `P90 <= value < P95`：`3`
- `P95 <= value < P99`：`5`
- `>= P99`：`8`

#### A 的最终计算

```text
A = A1 + A2
A <= 20
```

## 5. C. 同品种结构极值异常分

### 5.1 取值范围

- `0 ~ 60`

### 5.2 业务含义

`C` 是第一版最核心的分值。

它回答两个问题：

1. 目标合约相对同品种其他活跃合约，盘中结构偏离有多大
2. 这种偏离在同日横截面里，是不是明显只有它自己最突出

也就是说：

- 旧设计里想由 `C + D` 共同表达的事情
- 第一版现在统一由新的 `C` 表达

### 5.3 同日结构基线

对目标合约，先取同日活跃可比合约集合。
这里统一记它们的数量为：

- `active_peer_count`

第一版在这里显式约束：

- `active_peer_count >= 1`：允许继续评分
- `active_peer_count = 0`：直接视为无效样本

若同日活跃可比合约集合非空，则定义：

```text
peer_high_median = active_peer_contracts.high 的中位数
peer_low_median = active_peer_contracts.low 的中位数
peer_range_median = median((active_peer_contracts.high - active_peer_contracts.low) / active_peer_contracts.close)
```

再定义目标合约相对同日结构基线的单边残差：

```text
upper_residual = max(0, (high - peer_high_median) / close)
lower_residual = max(0, (peer_low_median - low) / close)
raw_structure_residual = max(upper_residual, lower_residual)
excess_structure_residual = max(0, raw_structure_residual - peer_range_median)
normalized_structure_residual = excess_structure_residual / peer_range_median
```

解释：

- 若只有目标合约的 `high` 被异常拉高，则 `upper_residual` 大
- 若只有目标合约的 `low` 被异常打低，则 `lower_residual` 大
- `raw_structure_residual` 只表示原始单边偏离幅度
- `excess_structure_residual` 表示该偏离在扣掉同日正常波动带后还剩多少
- `normalized_structure_residual` 则表示这个“超出正常波动带的部分”有多大

这里显式要求：

- 第一版不直接拿 `raw_structure_residual` 做评分
- 必须先用 `peer_range_median` 做同日波动背景归一化

这样可以区分两类情况：

1. 同日所有活跃合约本来都在大幅波动，目标合约只是略偏强或略偏弱
2. 目标合约相对同品种基线出现了明显超出同日正常波动带的单边尖刺

只有第二类，才应该在 `C` 上自然拿高分。

这里的关键点是：

- `C` 仍然使用 `close` 作为尺度归一化
- 但 **不使用 `close` 本身是否异常** 作为加分条件

也就是说，`close` 在 `C` 中只是价格尺度，不是判断对象。

### 5.4 评分逻辑

`C` 由两部分组成：

- `C1. 结构残差异常分`
- `C2. 同日唯一性分`

#### C1. 结构残差异常分：`0 ~ 40`

拿 `normalized_structure_residual` 与该合约过去 `20` 个有效交易日的历史分布比较。

这里的“有效历史分布”专指：

- `sample_status == valid`
- `active_peer_count >= 2`

的历史样本。

在此基础上：

- `< P90`：`0`
- `P90 <= value < P95`：`12`
- `P95 <= value < P99`：`24`
- `>= P99`：`40`

若该合约历史上的 `normalized_structure_residual` 长期接近 `0`，导致对应历史阈值也为 `0`，第一版增加一条兜底规则：

- 当历史阈值 `<= 0` 时，不再用该阈值做突破判断
- 改为使用固定的归一化下限：
  - `0.25`：进入第一档
  - `0.50`：进入第二档
  - `1.00`：进入第三档

这条兜底规则的目的不是补丁提分，而是避免下面这种情况：

- 历史上几乎从未出现过“超出同日正常波动带”的结构偏离
- 因此历史分位阈值全部压成 `0`
- 真正的孤立尖刺当天反而因为“0 不是有效阈值”而完全拿不到 `C1`

这部分回答的是：

- 你今天相对同品种结构，到底有没有超出同日正常波动带很多

#### C2. 同日唯一性分：`0 ~ 20`

对同日同品种所有活跃合约，分别计算各自的 `normalized_structure_residual`。

然后对目标合约定义：

```text
peer_normalized_residual_median = 其他活跃合约 normalized_structure_residual 的中位数
raw_uniqueness_gap = normalized_structure_residual - peer_normalized_residual_median
uniqueness_gap = max(0, raw_uniqueness_gap)
```

这里明确要求：

- `uniqueness_gap` 只保留正值部分
- 不再让“比同日其他合约更不突出”的负值进入历史分布

为了降低跨品种的固定阈值偏差，`C2` 不使用统一绝对百分比档位，而是改成：

- 先对 `uniqueness_gap` 建立该合约过去 `20` 个有效交易日的历史分布
- 历史样本仍要求：
  - `sample_status == valid`
  - `active_peer_count >= 2`

评分：

- `< P90`：`0`
- `P90 <= value < P95`：`5`
- `P95 <= value < P99`：`10`
- `>= P99`：`20`

若该合约历史上的 `uniqueness_gap` 长期接近 `0`，导致历史阈值也为 `0`，第一版同样增加兜底规则：

- 当历史阈值 `<= 0` 时，改为使用固定的归一化下限：
  - `0.25`：进入第一档
  - `0.50`：进入第二档
  - `1.00`：进入第三档

这部分回答的是：

- 你今天的结构偏离是不是在同日横截面里明显更突出

#### C 的最终计算

```text
C = C1 + C2
C <= 60
```

### 5.5 C 的设计含义

新的 `C` 不再包含：

- 收盘结构失真分
- 邻近参考完整度补分
- 主参考自身尖刺补分

这些逻辑之所以被移除，是因为它们会把三种不同语义混进 `C`：

1. 结构异常强度
2. 样本可信度
3. 针对个别案例的补丁逻辑

第一版要求 `C` 只表达：

- 盘中极值结构到底偏了多少，而且这个偏离是否已经超出同日正常波动带很多
- 这种偏离是不是在同日横截面里特别突出

## 6. E. 可信度惩罚分

### 6.1 取值范围

- `0 / -5 / -10 / -20`

### 6.2 业务含义

`E` 只负责一件事：

- 这条样本靠不靠谱

`E` 不负责：

- 奖励高流动性
- 判断异常强度
- 判断结构是否失真

### 6.3 评分逻辑

`E` 不是累加扣分，而是：

- 取所有适用惩罚中最重的一档

这里再明确一条：

- `active_peer_count = 1`：允许低可信度评分
- `active_peer_count = 0`：不允许正式评分

#### `E = 0`

满足：

- `sample_status == valid`
- 活跃可比合约数 `>= 3`
- `peer_comparability_weak_flag = False`
- `target_liquidity_weak_flag = False`

#### `E = -5`

满足：

- `sample_status == valid`
- 活跃可比合约数 `= 2`
- `peer_comparability_weak_flag = False`
- `target_liquidity_weak_flag = False`

#### `E = -10`

满足：

- `sample_status == valid`
- 活跃可比合约数 `>= 1`
- 并且满足任一：
  - `peer_comparability_weak_flag = True`
  - `target_liquidity_weak_flag = True`
  - 活跃可比合约数 `= 1`

这代表：

- 当前日样本仍可形成候选分
- 但它和“正常 peer 基线充分、目标流动性正常”的样本不属于同一可信度层级

#### `E = -20`

满足任一：

- `sample_status != valid`
- 活跃可比合约数 `= 0`

### 6.4 为什么 `E` 承接“参考完整度、可比性与目标流动性”

“参考完整度”“可比性稳定性”“目标合约自身流动性”本质上都不是异常强度，而是：

- 这条结构分值值不值得信

因此：

- 它应该进入 `E`
- 不应该再混进 `C`

### 6.5 无效样本的统一处理

若样本满足任一：

- `sample_status != valid`
- 活跃可比合约数 `= 0`

则统一按无效样本处理：

```text
A = 0
C = 0
E = -20
candidate_score = 0
```

这种样本保留在结果中，只用于：

- 解释为什么该日无法形成正式候选判断
- 区分“没有异常”与“数据不足/对照不足”

第一版实现中，常见无效样本状态包括：

- `invalid_basic_data`
- `invalid_low_liquidity`
- `invalid_lifecycle_edge`
- `invalid_insufficient_history`
- `invalid_insufficient_peer`

## 7. 候选等级判定

### 7.1 分数到等级的映射

第一版建议固定为：

- `< 30`：`none`
- `30 ~ 49`：`low`
- `50 ~ 64`：`medium`
- `>= 65`：`high`

### 7.2 结构异常优先约束

由于 `C` 是核心分项，增加两个约束：

- 若 `C < 20`，最高只能到 `low`
- 若 `C < 35`，不能到 `high`

### 7.3 设计原则

等级不能成为修补评分的地方。

也就是说：

- 不能为了让某条记录看起来更合理，就在等级层单独抬档
- 若某类场景业务上明显应该更高，优先修改 `A/C/E`
- 等级层只负责映射，不负责“补提分”

## 8. 为什么第一版不再把 `close` 修复信息放进主评分

第一版不是说：

- `close` 完全没价值

而是说：

- `close` 不再作为“盘中结构异常是否存在”的主证据

原因是：

1. 乌龙指可能发生在任何时间段，主证据更容易体现在异常 `high/low`
2. 真正瞬时的异常成交，往往到收盘已经看不出来
3. 如果把 `close` 修复程度放进主评分，容易把“瞬时尖刺”和“普通回补日”混在一起

因此第一版的选择是：

- `A` 中保留 `close` 作为当天价格尺度
- `C` 中只对 `high/low` 做结构判断
- 若后续需要展示“收盘是否修复”，应优先作为报告解释字段，而不是主加分项

## 9. 校验样本原则

第一版评分体系仍然要求：

- 对像 `AU2606 2026-05-20` 这样的典型单合约尖刺样本，系统应该自然给出高分

但这里的“自然给高分”指的是：

- `A` 高：因为自身极值异常极强
- `C` 高：因为相对同日其他活跃合约的结构偏离极强，且明显只有它自己最突出
- `E` 不重罚：因为样本仍有足够的活跃对照

而不是：

- 通过单独的案例补分项去把它硬抬上去

## 10. 文档维护规则

后续如果调整以下任何内容，应优先修改本文档：

- `A/C/E` 的取值范围
- 任一分项公式
- 活跃合约定义
- 可比性稳定规则
- 目标合约自身流动性规则
- 分位数阈值
- 可信度惩罚规则
- `high / medium / low` 等级阈值
- 等级与结构分的约束关系
